# 产品 MVP 与可信边界

> 适用范围：A 股数据分析平台当前阶段。本文用于约束产品承诺、前后端展示、AI 输出和上线门禁，不构成投资建议。

## 一句话定位

当前 MVP 聚焦普通散户的高频场景：发现值得继续研究的 A 股线索，理解它为什么入池，并持续跟踪数据风险、公告风险、价格预警和自选股变化。

平台不是荐股工具，不承诺实时交易信号，不提供买入、卖出、仓位比例或收益保证。

## 核心用户与主路径

核心用户：普通散户或轻量研究用户。

主路径：

1. 进入首页查看“今日观察”。
2. 先看可信状态、候选来源和数据等级。
3. 点击个股详情，核对行情、K 线、资金流、新闻、公告、财报和 AI 摘要。
4. 只在数据来源可信时加入自选或创建预警。
5. 后续通过自选、预警和详情页持续跟踪，而不是把观察池当成买入清单。

## 当前 MVP 必须做好

- 数据可信展示：每个观察池候选必须能看到候选来源、数据等级、风险标签和降级提示。
- 生产安全底线：默认密钥、默认管理员、生产占位密码、AI Key 明文落地必须被配置门禁拦住。
- 真实失败可见：采集任务失败、scheduler 停止、服务 5xx 和 metrics 掉线必须能被 Prometheus 发现。
- 非投资建议边界：首页、观察池、AI 分析、详情页风险区域必须明确区分“事实数据、规则评分、模型推断、用户自行判断”。
- 可回归验证：后端单测、前端类型检查、构建和 smoke 必须作为交付门禁持续通过。

## 当前 MVP 不承诺

- 不承诺逐笔、盘口、毫秒级实时行情。
- 不承诺所有 A 股全量覆盖都有完整行情、资金流、公告、财报和新闻。
- 不承诺观察池结果适合买入。
- 不承诺 AI 输出是事实结论；AI 只能解释和总结已有上下文。
- 不承诺 fallback、empty、unavailable 状态下的候选可用于真实跟踪或加入自选。

## 数据可信等级

| 状态 | 用户含义 | 产品处理 |
| --- | --- | --- |
| 可观察 | 候选来自数据库和规则评分 | 可展示、可进入详情、可加入自选 |
| 需复核 | 有警告、有效评分不足或部分数据缺失 | 可展示，但必须提示风险 |
| 调试数据 | 使用 fallback 候选池 | 只能验证页面流程，禁用加入自选 |
| 不可用 | 候选池为空或服务不可用 | 不展示为有效观察结果 |

## AI 输出边界

AI 分析必须遵守四层表达：

- 事实数据：来自行情、K 线、公告、财报、新闻或本地缓存，必须带来源或数据质量提示。
- 规则评分：来自后端评分规则，必须展示评分明细和风险灯。
- 模型推断：必须说明是基于当前上下文的推断，不得包装成确定结论。
- 禁区：不得输出买入、卖出、满仓、止盈止损价、收益承诺等指令式建议。

## 上线前硬门槛

- `python scripts/verify_delivery.py` 通过。
- `npm run smoke:frontend` 通过。
- `docker compose config` 在具备 Docker 的环境通过。
- Prometheus 能抓到四个后端服务和 data-crawler 的 `/metrics`。
- 生产环境必须显式配置 `DB_PASS`、`GRAFANA_PASS`、`JWT_SECRET`、`AI_ENCRYPTION_KEY`。
- fallback 候选不能被当成真实推荐，也不能加入自选。

## 后续优先级

1. 补齐真实数据源完整性：实时行情、周/月 K、资金流、公告和财报的成功率与新鲜度。
2. 建立真正 E2E：登录、观察池、详情页、自选、预警、AI 分析全链路。
3. 接入 Grafana 看板和告警通知渠道。
4. 拆分超长后端路由，沉淀评分规则和 AI 上下文构建服务。
5. 用 ADR 记录关键架构决策，避免产品边界再次发散。
